# External Technical Research Notes — RC1.5

## Current project facts checked locally

The Unity project is `2022.3.40f1`. Its manifest declares `com.atteneder.gltfast` `6.0.1`, `com.unity.ai.navigation` `1.1.5`, and URP `14.0.11`. Static source inspection found no `GltfImport` call in `Assets`; the project uses a custom synchronous parser. Do not infer that current upstream Unity glTFast 6.20.x can be substituted directly for the declared atteneder package without a Unity 2022.3 compatibility check.

## Sources and decisions

- Official Unity glTFast runtime import guide: https://github.com/Unity-Technologies/com.unity.cloud.gltfast/blob/main/Packages/com.unity.cloud.gltfast/Documentation~/ImportRuntime.md — describes async loading from URI/bytes, scene instantiation, settings, logging, disposal, and a frame-budgeted defer agent. It warns that `true` means no critical import error and partial failures can still occur, so logs/results need inspection. The project’s existing 6.0.1 package and Unity 2022.3 version must be checked before adopting newer API details.
- Official glTFast memory-loading example: https://raw.githubusercontent.com/Unity-Technologies/com.unity.cloud.gltfast/main/Packages/com.unity.cloud.gltfast/Runtime/DocExamples/LoadGltfFromMemory.cs — demonstrates `GltfImport.Load(byte[], Uri)` and `InstantiateMainSceneAsync`; newer source also shows legacy animation access behind a compile symbol.
- Current upstream glTFast package metadata: https://github.com/Unity-Technologies/com.unity.cloud.gltfast/blob/main/Packages/com.unity.cloud.gltfast/package.json — fetched `6.20.1-pre.1`, Unity requirement `6000.0`; this is not the same package ID/version as the project’s `com.atteneder.gltfast` `6.0.1`.
- Unity mobile technical-art optimization guide: https://unity.com/how-to/mobile-game-optimization-tips-part-1 — recommends silhouette-first geometry, selective LODs, simple material/shader budgets, texture-size/color-space control, compressed textures, and profiling the actual view. It is guidance, not measured performance evidence for this project.

## Candidate asset provenance

The initial barrier model was created with Manus `generate_3d_model` from a text prompt, saved to `/home/ubuntu/ProjectRealLoserUnity/generated/prop_concrete_barrier_a_candidate.glb` on 2026-10-20. First static parse: GLB 2.0; 1 node, 1 mesh, 1 primitive; 6,871 vertices and 6,424 triangles; UV0 present; one factor-only PBR material plus 3 embedded image textures (base color JPEG, ORM JPEG, normal PNG); model-space bounds approximately `[-0.5,-0.379,-0.261]` to `[0.498,0.392,0.257]`. It therefore does **not** meet the brief’s 3,500-triangle target or ground-pivot/2.4m dimensions without normalization, and is not yet integrated or production-approved. The current custom runtime loader ignores UVs and embedded images, so these textures will not appear until that loader is extended or a compatible runtime importer is used.
